## 1. ความเร็ว 1× / 1.5× / 2× คืออะไร

**คือการเร่งวิดีโอทดสอบให้เหมือนคนทำท่าเร็วขึ้น**

ประโยค TSL51 อัดจากคนที่ทำท่าค่อนข้างช้า (~2.4 วินาทีต่อคำ) แต่คนใช้งานจริง (เช่น ทำท่าหน้ามือถือ) มักทำเร็วกว่า → อยากรู้ว่าถ้าทำเร็ว ระบบยังทายได้ไหม

| ความเร็ว | ทำยังไง | เหมือน |
|---|---|---|
| **1×** | ใช้วิดีโอตามจริง | คนทำท่าความเร็วปกติ (ช้า-ชัด) |
| **1.5×** | บีบวิดีโอให้สั้นลงเหลือ 2/3 (เช่น 75 เฟรม → 50 เฟรม) | คนทำท่าเร็วขึ้น 1.5 เท่า |
| **2×** | บีบเหลือครึ่งเดียว (75 → 38 เฟรม) | คนทำท่าเร็ว 2 เท่า |

```
1×   ■■■■■■■■■■■■■■■■■■■■  (ทุกเฟรม)
1.5× ■■■■■■■■■■■■■         (เลือกเฟรมห่างขึ้น → ท่าจบเร็วขึ้น)
2×   ■■■■■■■■■■            (ข้ามทุกเฟรมเว้นเฟรม)
```
(โค้ด: `modules/segment.py` ฟังก์ชัน `resample` — เลือกเฟรมห่างขึ้นแล้วเฉลี่ยตำแหน่งระหว่างเฟรม)

**ทำไมสำคัญ:** ตอนทำท่าเร็ว ท่าสั้นลง → ระบบมัก "**ทำคำหาย**" (ข้อ 9 รอบก่อนพบว่าที่ 2× คำหายเยอะ) → เราเลยวัดทั้ง 3 ความเร็วเสมอ และกติกาคือ**ห้ามแย่ลงทุกความเร็ว**

 │     ▼                                                                 │
 │  ขั้น 2  สอน encoder        (ทายว่าท่านี้คือคำอะไร)        [GPU]     │

## 3. ขั้น 1 — เตรียมข้อมูล (prep)

**เป้าหมาย:** เปลี่ยนวิดีโอดิบเป็นข้อมูลที่โมเดลกินได้ + จัดกลุ่มให้วัดผลแบบยุติธรรม

| ขั้นย่อย | ทำอะไร | ได้อะไร |
|---|---|---|
| 1.1 รวบรวมวิดีโอ | วิดีโอภาษามือจาก 5 แหล่ง (TTRS, THSL, ONE, YouTube/AGENT, TSL51) เก็บบน S3 | `cloud_s3/raw_data/` |
| 1.2 ดึงจุดบนร่างกาย | **MediaPipe** หาจุด 133 จุดทุกเฟรม (ตัว 23 · หน้า 68 · มือซ้าย 21 · มือขวา 21) | ไม่ได้ดูภาพอีกต่อไป ดูแค่จุดพวกนี้ |
| 1.3 ทำความสะอาด | หาช่วงที่ทำท่าจริงในคลิป (`span`), กลับซ้าย-ขวาให้มือถนัดอยู่ด้านเดียวกัน, ปรับขนาดตามความกว้างไหล่ | ทุกคลิปอยู่ในมาตรฐานเดียวกัน |
| 1.4 ติดป้าย | คลิปนี้คือคำอะไร (`concept`) · ใครทำ (`signer`) | ตาราง `clips.parquet` |
| 1.5 **แบ่งกลุ่ม** | แบ่งตาม**คน** ไม่ใช่ตามคลิป → คนใน test ไม่เคยโผล่ใน train | `role` = train / val / test |
| 1.6 แพ็ก | รวมจุดทุกคลิปเป็นไฟล์เดียว | `cloud_s3/data_prep/shards/pose_store.npz` (1.2 GB) |

**ทำไมแบ่งตาม "คน":** ถ้าคนเดียวกันอยู่ทั้งตอนสอนและตอนสอบ ระบบอาจ "จำคนได้" แทน "เข้าใจท่า" → คะแนนดีเกินจริง

**ผลของการแบ่ง:**
| กลุ่ม | ใช้ทำอะไร |
|---|---|
| **train** | สอนโมเดล + ใส่ใน bank |
| **val** | เลือกค่า / เลือกโมเดล |
| **test** | รายงานผล (ดูครั้งเดียว) |
| TSL51 ประโยค **tune** (`tagger_train`, 126) | สอน tagger + เลือกค่าตัวตัดคำ |
| TSL51 ประโยค **test** (126) | รายงานผลประโยค |

คำสั่ง (ของเพื่อน): `python main.py prep <step>`, `python main.py extract`

## 4. ขั้น 2 — สอน encoder (ทายคำ)

**encoder ทำอะไร:** รับท่า 1 ช่วง → แปลงเป็นตัวเลข 768 ตัว ("ลายนิ้วมือของท่า") · ท่าเดียวกัน = ตัวเลขใกล้กัน · ท่าต่างกัน = ตัวเลขห่างกัน

**สอนยังไง:**
1. **เริ่มจากโมเดลสำเร็จรูป** (Uni-Sign — เคยเรียนภาษามือจีน CSL-News + อเมริกัน WLASL มาแล้ว) → ไม่ต้องเริ่มจากศูนย์
2. **สอนต่อด้วยภาษามือไทย** (คลิป train): บอกโมเดลว่า "คลิปนี้กับคลิปนั้นคือคำเดียวกัน (คนละคน) → ทำตัวเลขให้ใกล้กัน · คำต่างกัน → ทำให้ห่าง"
3. ระหว่างสอน **บิดข้อมูล** (augmentation) — หมุน ย่อ เร่ง สลับซ้ายขวา — ให้ทนต่อความต่างเล็กๆ
4. ทุกๆ ช่วง วัดผลบน **val** → เก็บรุ่นที่ดีที่สุด

- รันบน **GPU** (เพื่อน: Google Vertex AI · เรา: Modal) ~40 นาที
- ได้: `encoder_best.pt` + ตัวเลขของทุกคลิป (`emb.npy`)
- โค้ด: `GCP/script/job_entry.py --stage train_encoder`, `modules/encoder.py`

## 5. ขั้น 3 — สอน tagger (หาจุดตัดคำ)

**tagger ทำอะไร:** ดูทีละเฟรม ตอบ 3 อย่าง → **ไม่ได้ทำท่า / เริ่มคำใหม่ / อยู่ในท่าเดิม** · ใช้หาว่าในประโยคยาวๆ คำไหนเริ่ม-จบตรงไหน

**ปัญหา:** การสอน tagger ต้องมีประโยคที่**รู้ว่าแต่ละคำเริ่ม-จบเฟรมไหน** — ซึ่งแทบไม่มี (มีแต่คำเดี่ยว)

**ทางแก้ของเพื่อน — สร้างประโยคปลอม:**
```
คลิปคำเดี่ยว "ฉัน" + คลิป "รัก" + คลิป "เพื่อน"   →   ต่อกันเป็นประโยค
                                                   รู้ทุกเฟรมว่าเป็นคำไหน (เพราะเราต่อเอง)
```

**ขั้นย่อย (โค้ด `modules/sequence.py` → `stage_sequence`):**
| # | ทำอะไร |
|---|---|
| 3.1 | สร้างประโยคปลอม 2,500 ประโยค จากคลิป **train** (สุ่ม 2–6 คำ, สุ่มความเร็ว 0.8–2.4×, ใส่ช่วงพัก/ค้างบ้าง) |
| 3.2 | สร้างประโยคปลอมอีก 240 ประโยคจากคลิป **val/test** ไว้เลือกรุ่นที่ดีที่สุด |
| 3.3 | สอน **span head** (ตัวช่วยที่ทำให้ทายคำในประโยคเร็วขึ้น ไม่ต้องรัน encoder ทุกช่วง) |
| 3.4 | เดาจุดตัดคำในประโยค TSL51 ส่วน tune ("forced alignment" — รู้ว่ามีคำอะไรเรียงยังไง แค่หาตำแหน่ง) |
| 3.5 | **สอน tagger** ด้วย ประโยคปลอม + TSL51 tune (+ ฉบับเร่ง 1.5×/2×) — 18 รอบ เก็บรอบที่ดีที่สุด |

- tagger = **BiGRU** (อ่านทั้งประโยคไปข้างหน้าและย้อนกลับ) · ข้อมูลเข้าต่อเฟรม = ตัวเลขจาก encoder (768) + การเคลื่อนไหว 13 ค่า (เห็นมือไหม มือสูงแค่ไหน เร็วแค่ไหน ห่างจมูกเท่าไหร่ รูปมือเปลี่ยนไหม)
- รันบน GPU ~10–15 นาที (เฉพาะส่วนที่ได้ tagger หลัก)
- ได้: `tagger.pt`, `span_head.npz`

**⭐ จุดที่เราแก้:** ประโยคปลอมของเพื่อนมี "การหยุดนิ่งก่อน-หลังท่า" ทุกคำ → tagger เรียนผิดทาง · เราเพิ่มตัวเลือก `--fluent` ให้บางส่วนเป็น**ประโยคแบบลื่น** (ตัดหัว-ท้ายท่า + เชื่อมให้กลืน)

## 6. ขั้น 4 — สร้าง bank + แพ็กโมเดล

| ทำอะไร | ได้อะไร |
|---|---|
| เอาตัวเลข (จาก encoder) ของทุกคลิปตัวอย่าง มารวมเป็นคลัง | **`models/bank.npz`** — คลังที่ระบบใช้จริง (ทุกคน ~19,600 คลิป) |

คำสั่ง (ของเพื่อน): `python main.py eval build`, `python main.py export-onnx`

## 7. ขั้น 5 — ใช้งานจริง

```
วิดีโอ / กล้อง
  ① MediaPipe          → จุดบนร่างกาย 133 จุด ทุกเฟรม
  ② tagger             → ทุกเฟรม: ไม่ได้ทำท่า / เริ่มคำใหม่ / อยู่ในท่า
  ③ ตัวตัดคำ           → เลือกช่วงคำที่ดีที่สุด (ใช้ผลจาก ② + คะแนนว่าช่วงนั้นเหมือนคำไหน)
  ④ encoder + bank     → แต่ละช่วง → ตัวเลข → เทียบคลัง → คำที่เหมือนที่สุด 5 อันดับ
  ⑤ สีหน้า + ภาษา      → คิ้ว/ส่ายหัว → คำถาม/ปฏิเสธ · เรียงคำเป็นประโยคไทย (+ LLM)
  ⑥ TTS                → เสียงพูด
```
- โค้ดหลัก: `modules/pipeline.py` (`SignPipeline.run_landmarks`)
- ใช้ผ่าน: เว็บเดโม (`docker compose up` → http://localhost:8080) หรือ `python main.py infer --video ...`

## 8. เราทดสอบยังไง

### 8.1 ตารางรวมทุกการทดสอบ

| การทดสอบ | ข้อมูล | วัดอะไร | ตัววัด | ตอบคำถาม | สคริปต์ |
|---|---|---|---|---|---|
| **คำเดี่ยว** | คลิปคำเดี่ยวของคน val/test (TTRS, THSL, ONE, AGENT, T51U) | ทายคำถูกไหม | **R@1** (สูง=ดี) | encoder เก่งแค่ไหน | ใน `job_entry.py` / `analyze_failures.py` |
| **ประโยค TSL51** ⭐ | 252 ประโยคจริง (tune/test) × ความเร็ว 1× / 1.5× / 2× | ทั้งระบบ ทายประโยคถูกไหม | **WER** (ต่ำ=ดี), recall | ระบบอ่านประโยคได้ดีแค่ไหน | `pitty/scripts/sentence_eval.py` |
| **ประโยคแบบลื่น** (ใหม่) | ประโยคปลอมแบบลื่น 240 ประโยค จากคลิปคน val/test (same / diff) | ทั้งระบบ เมื่อทำท่าต่อเนื่อง | WER, ทายถูก, จำนวนคำที่ตัดได้ | แยกคำในการทำท่าต่อเนื่องได้ไหม | `pitty/scripts/fluent_eval.py` |
| **TSL51 ตัดช่วงค้าง** (ใหม่) | TSL51 test `no_space` ที่ตัดช่วงมือนิ่งระหว่างคำออก | เหมือนข้างบน แต่เป็นท่าคนจริง | WER | (ข้อมูลเสริม) | `sentence_eval.py` + `HOLD_CUT` |
| **data_test** | วิดีโอจริง 5 คลิป (zip จาก Drive) | ทั้งระบบตั้งแต่วิดีโอ | ทายถูก (ไม่สนลำดับ) | ใช้งานจริงได้ไหม (ดูอย่างเดียว) | `python main.py test` |
| **jack_test** | คลิปตัวอย่างคำ/ตัวอักษร | คำเดี่ยว + สะกดนิ้ว | ทายถูก | โหมดสะกดนิ้วทำงานไหม | (สคริปต์ชั่วคราว) |
| **จับมือ** (รอบก่อน) | วิดีโอ 64 คลิป | มือหลุดเฟรม | % เฟรมที่มือหาย | MediaPipe ตั้งค่ายังไงดี | `pitty/scripts/hands_extract_*.py` |
| **ตัวตรวจรอยต่อ** (ใหม่) | ประโยคใดๆ + tagger ของเพื่อน | tagger เห็นรอยต่อแค่ไหน | ท่อนต่อคำ (เป้า 0.25) | ประโยคปลอมเหมือนจริงไหม | `pitty/scripts/fluent_synth.py check` |

### 8.2 ตัววัด อ่านยังไง
| ตัววัด | คำนวณยังไง | ตัวอย่าง |
|---|---|---|
| **R@1** | ทายถูกเป็นอันดับแรก / ทั้งหมด | 90 จาก 100 คลิป = 0.90 |
| **WER** | (ทายผิดคำ + คำหาย + คำเกิน) ÷ จำนวนคำจริง | เฉลย 4 คำ ผิด 1 หาย 1 → 2/4 = 0.50 |
| **recall** | คำในเฉลยที่โผล่ในผล (ไม่สนลำดับ) | เฉลย 4 คำ โผล่ 3 → 0.75 |
| **ท่อนต่อคำ** | เส้น "กำลังทำท่า" ของ tagger ขาดเป็นกี่ท่อน ÷ จำนวนคำ | 4 คำ 1 ท่อน → 0.25 (มองไม่เห็นรอยต่อ) |

### 8.3 ทดสอบแบบไหน "ใช้ bank อะไร"
- ทุกการทดสอบ**ประโยค**ใช้ `bank_eval.npz` (**เฉพาะคน train**) → คนในข้อสอบไม่อยู่ในคลัง
- ตัวตั้งค่าตัวตัดคำ = `models/spotting.json` (เหมือนกันทุกตัวที่เทียบ ยกเว้นตอนทดลองปรับ)
- เปลี่ยนแค่ "สิ่งที่อยากทดสอบ" ทีละอย่าง (เช่น สลับ tagger ด้วย `TAGGER_ONNX=...`)

## 9. กติกาที่ใช้ตัดสิน

| กติกา | ทำไม |
|---|---|
| **เลือกด้วย tune/val → ดู test ครั้งเดียว** | ถ้าดู test บ่อย จะเผลอเลือกสิ่งที่บังเอิญดีกับ test |
| **ต้องมีตัวควบคุม** (train เหมือนกันทุกอย่าง ยกเว้นสิ่งที่ทดสอบ) | แยกให้ออกว่าดีขึ้นเพราะวิธีใหม่ หรือแค่เพราะ train ใหม่ |
| **ดู 95% CI** (paired bootstrap: สุ่มประโยคซ้ำ 10,000 รอบ) | ไม่คร่อม 0 = ต่างจริง · คร่อม 0 = อาจบังเอิญ |
| **TSL51 ทุกความเร็วห้ามแย่ลง** | แก้ปัญหาใหม่ต้องไม่ทำของเดิมพัง |
| **data_test ดูอย่างเดียว** | มี 5 คลิป ถ้าใช้เลือกจะ overfit |
| **รัน baseline ใหม่ด้วยโค้ดปัจจุบัน** | ผลเก่าอาจมาจากโค้ด/ตั้งค่าที่ต่างกัน |

## 10. เราไปแก้ตรงไหนของกระบวนการ

| ขั้น | ของเดิม (เพื่อน) | เราลอง/แก้ | ผล |
|---|---|---|---|
| 1 prep / ใช้งาน | ปรับแสงทั้งภาพอัตโนมัติ | **ปิด** | ✅ มือหายลดจาก 19.8% → 8.9% (ใช้อยู่) |
| 2 encoder | บิดข้อมูลแบบเดิม | เพิ่มบิดมุมกล้อง/มือ | ❌ ไม่ต่าง (คืนค่าแล้ว) |
| 3 tagger | ประโยคปลอมมีหยุดนิ่งทุกคำ | **ผสมประโยคแบบลื่น 25%** | ✅ แยกคำในการทำท่าต่อเนื่องดีขึ้น ไม่ทำของเดิมแย่ลง (ใช้อยู่) |
| 4 bank | – | เพิ่มคลิปบิด / รวมชื่อคำซ้ำ | ❌ / ⚪ (ไม่ได้ใส่) |
| 4 ตั้งค่าตัวตัดคำ | `min_frames` 14 | **10** | ✅ ทำท่าเร็ว 2× ดีขึ้น (ใช้อยู่) |
| 4 ตั้งค่าตัวตัดคำ | `lam` 6 | ลอง 12 | ❌ ทำท่าเร็วแย่ลง |
| ทดสอบ | TSL51 อย่างเดียว | **เพิ่มชุดประโยคแบบลื่น** + ตัวตรวจรอยต่อ | ทำให้เห็นปัญหาการทำท่าต่อเนื่องที่ซ่อนอยู่ |

**ข้อมูลที่แก้ความเข้าใจผิด:** TSL51 ส่วนใหญ่ (228/252) อัดแบบ `no_space` (ไม่เว้นช่วง) และคน**ไม่ได้ลดมือพัก**ระหว่างคำ — แต่ทำท่า**ช้ากว่าและค้างมือนิ่ง**ระหว่างคำ (~1 วินาที) ซึ่งพอให้ tagger เห็นรอยต่อ ต่างจากคนใน data_test ที่ทำเร็วและลื่น · ลองตัดช่วงค้างออกแล้ว tagger ก็ยังเห็นรอยต่ออยู่ (0.70 ท่อนต่อคำ) → ความต่างอยู่ที่**สไตล์การทำท่า**ของแต่ละคนด้วย ไม่ใช่แค่ช่วงค้าง
