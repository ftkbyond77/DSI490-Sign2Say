## 1. สรุปทั้งหมดใน 1 หน้า

| คำถาม | คำตอบสั้น |
|---|---|
| ระบบดูท่า**ทีละคำ**ได้ไหม | **ได้ดี** — ทายถูก ~90% กับคนที่ระบบไม่เคยเห็น |
| ระบบดูท่า**เป็นประโยค**ได้ไหม | **ยังไม่ดี** — ทายถูก ~50% |
| ทำไมประโยคแย่ | เวลาคนทำท่า**ต่อเนื่องไม่หยุด** ระบบ**หาไม่เจอว่าคำหนึ่งจบตรงไหน คำถัดไปเริ่มตรงไหน** เลยตัดคำผิดที่ |
| ทำไมหาไม่เจอ | ส่วนที่ทำหน้าที่ "หาจุดตัดคำ" (เรียกว่า **tagger**) ถูกสอนจากคลิปคำเดี่ยว ซึ่ง**มีการหยุดนิ่งก่อน/หลังทุกท่า** มันเลยเรียนว่า "ตรงที่หยุดนิ่ง = รอยต่อ" — แต่คนทำท่าจริงไม่หยุด |
| แก้ยังไง | สร้าง**ประโยคปลอมแบบลื่น** จากคลิปคำเดี่ยว (ตัดช่วงหยุดนิ่งทิ้ง แล้วเชื่อมให้กลืนกัน) แล้ว**สอน tagger ใหม่** |
| ได้ผลไหม | ✅ กับประโยคปลอมแบบลื่น: ทายถูกขึ้นชัด (0.25 → 0.34) · ✅ กับท่าคนจริงที่ตัดช่วงค้าง (TSL51): WER 0.630 → 0.581 · ✅ ไม่ทำให้ TSL51 ปกติแย่ลง · ⚪ วิดีโอจริง 5 คลิป: เท่าเดิม (คลิปน้อยเกินจะสรุป) |
| ตอนนี้ระบบในเครื่องใช้อะไร | tagger ตัวใหม่ (**A 25%**) + การปิดปรับแสงอัตโนมัติ (ทำให้**จับมือได้ดีขึ้น** — เห็นเองตอนลองเว็บเดโม) |
| ลองอะไรแล้วไม่ได้ผล | augmentation ทุกแบบ (บิดภาพ/มุมกล้อง), train encoder ใหม่, ปรับตัวเลขตัวตัดคำ, ทำประโยคปลอมให้ลื่นขึ้นอีก (v2) |
| ขั้นต่อไปที่สำคัญที่สุด | **อัดวิดีโอประโยคที่ทำท่าต่อเนื่องจริง 30–50 ประโยค** ไว้วัดผล — ตอนนี้มีแค่ 5 คลิป เลยตัดสินกับการใช้งานจริงไม่ได้ |

## 2. ระบบ ThaiSLM ทำงานยังไง

### 2.1 ภาพรวม (เหมือนสายพานโรงงาน)

```
วิดีโอ / กล้อง
   │
   ▼  ① MediaPipe — หาจุดบนร่างกาย (keypoints): ข้อมือ นิ้ว ไหล่ หน้า … ทุกเฟรม
   │
   ▼  ② tagger — ดูทีละเฟรมว่า "กำลังทำท่าไหม / คำใหม่เริ่มตรงนี้ไหม"   ← ⭐ งานรอบนี้แก้ตรงนี้
   │
   ▼  ③ ตัวตัดคำ (decoder) — ใช้ผลจาก ② ตัดวิดีโอเป็นช่วงๆ ช่วงละ 1 คำ
   │
   ▼  ④ encoder + bank — แต่ละช่วง → แปลงเป็นตัวเลข → เทียบกับ "คลังคลิปตัวอย่าง" ว่าเหมือนคำไหนที่สุด
   │
   ▼  ⑤ สีหน้า + เรียงประโยค — คิ้ว/ส่ายหัว → คำถาม/ปฏิเสธ · เรียงคำเป็นประโยคไทย (+LLM)
   │
   ▼  ⑥ เสียงพูด (TTS)
```

**เปรียบเทียบให้เห็นภาพ:** เหมือนฟังคนพูดภาษาต่างประเทศ
- ④ = **รู้ศัพท์** (ได้ยินคำเดียวแล้วรู้ว่าแปลว่าอะไร) — ระบบเก่งแล้ว
- ②③ = **แยกคำออกจากกัน** ตอนเขาพูดรัวๆ — ระบบยังแย่ ← ปัญหาหลัก

### 2.2 ข้อมูลที่ระบบมี

| ชุดข้อมูล | คืออะไร | หมายเหตุ |
|---|---|---|
| คลิป**คำเดี่ยว** ~19,000 คลิป จาก 5 แหล่ง (TTRS, THSL, ONE, AGENT, TSL51) | คนทำท่าทีละคำ | **ข้อมูลเกือบทั้งหมดเป็นแบบนี้** |
| ประโยค **TSL51** 252 ประโยค | คนเดียวทำท่าเป็นประโยค (228 แบบ `no_space` ไม่เว้นช่วง + 24 แบบเว้นช่วง) | แต่ทำ**ช้าและค้างมือนิ่งระหว่างคำ** → tagger ยังเห็นรอยต่อ |
| **data_test** (zip จาก Drive) 5 คลิป | วิดีโอประโยคจริง | 3 คลิปทำท่า**ต่อเนื่อง** · ใช้ดูอย่างเดียว |
| **jack_test** (zip จาก Drive) | คลิปตัวอย่างคำ/ตัวอักษร ไว้ให้คนดูฝึกทำท่า | ไม่ใช่ชุดทดสอบ (ส่วนใหญ่อยู่ใน train อยู่แล้ว) |

**ข้อจำกัดของโปรเจกต์:** มีแต่คำเดี่ยว แต่อยากให้อ่านประโยคได้ → ทั้งหมดในรอบนี้คือการหาทาง "ใช้คำเดี่ยวสอนให้เข้าใจประโยค"

## 3. เราวัดว่า "ดีขึ้น" ยังไง

### 3.1 ตัวเลขที่ใช้
| ตัวเลข | ความหมาย | ดีคือ |
|---|---|---|
| **R@1** (ทายถูกอันดับ 1) | จากคำทั้งหมด ทายถูกเป็นอันดับแรกกี่ % | สูง |
| **WER** (word error rate) | ประโยคผิดไปกี่ % (ทายผิดคำ + คำหาย + คำเกิน) ÷ จำนวนคำจริง | **ต่ำ** |
| **recall** | คำในเฉลย มีโผล่ในผลลัพธ์กี่ % (ไม่สนลำดับ) | สูง |
| **ช่วงทำท่าต่อคำ** | tagger แยกได้กี่ช่วงต่อ 1 คำ — 1.0 = เห็นรอยต่อทุกคำ · 0.25 = แทบไม่เห็น | ใช้วัดว่าประโยคปลอม "เหมือนจริง" แค่ไหน (ของจริงทำท่าต่อเนื่อง = 0.25) |

### 3.2 กฎที่ใช้ตัดสิน (ป้องกันการหลอกตัวเอง)
1. **แบ่งข้อมูลเป็น 2 ส่วน:** ส่วน **tune/val** ใช้ลองและเลือก · ส่วน **test** เก็บไว้ดู**ครั้งเดียว**ตอนเลือกเสร็จ (ถ้าดู test บ่อยๆ จะเผลอเลือกสิ่งที่บังเอิญดีกับ test)
2. **ต้องมี "ตัวควบคุม":** ถ้า train โมเดลใหม่ด้วยวิธี X ต้อง train อีกตัว**เหมือนกันทุกอย่างแต่ไม่มี X** — เพื่อรู้ว่าที่ดีขึ้นเพราะ X จริง ไม่ใช่เพราะแค่ train ใหม่
3. **ดูความไม่แน่นอน (95% CI):** ผลต่างที่ได้ อาจบังเอิญก็ได้ → คำนวณช่วงความเชื่อมั่น ถ้าช่วง **ไม่คร่อม 0** (เช่น [−0.14, −0.04]) = ต่างจริง · ถ้าคร่อม 0 (เช่น [−0.02, +0.03]) = อาจบังเอิญ ถือว่าเท่ากัน
4. **ห้ามทำให้ของที่ดีอยู่แล้วแย่ลง:** ประโยค TSL51 ทุกความเร็วต้องไม่แย่ลงอย่างมีนัยสำคัญ
5. **data_test ดูอย่างเดียว** ไม่ใช้เลือก (มีแค่ 5 คลิป)

### ข้อ 13 — ลอง "เพิ่มคลิปบิด" ใน bank ❌
- **ไอเดีย:** เอาคลิปตัวอย่างใน bank มาบิดนิดหน่อย (หมุน ย่อ ขยาย เร่ง) แล้วเพิ่มเข้า bank → มีตัวอย่างหลากหลายขึ้น
- **ผล:** คะแนน val **แย่ลง** (0.524 → 0.511–0.521) → ไม่ใช้

### ข้อ 14 — ลอง train encoder ใหม่ + บิดมุมกล้อง/มือ (GPU A100 บน Modal) ❌
- **ไอเดีย:** สอน encoder ให้ไม่สนมุมกล้อง/ขนาดมือ โดยตอน train บิดข้อมูลแบบ "กล้องหันเฉียง" "หมุนมือ" "แขนกว้าง/แคบ"
- **ทำยังไง:** เขียนโค้ดบิด 3 แบบ → ทดสอบว่าปิดแล้วเหมือนเดิมเป๊ะ → train 2 ตัวบน GPU: **ctrl** (ไม่บิด = ตัวควบคุม) กับ **aug** (บิด)
- **ผล:** aug = ctrl (0.4906 vs 0.4901) และบางชุดแย่ลง → **ไม่ใช้ คืนค่าโค้ดแล้ว**

### ข้อ 15 — วิเคราะห์ว่าทำไมชุด TTRS / THSL ได้คะแนนต่ำ 🔍
- **ทำยังไง:** ดูทุกคลิปที่ทายผิด แล้วหาว่ามันต่างจากที่ทายถูกยังไง (มือหาย? คนไม่เคยเห็น? คำนั้นมีตัวอย่างกี่คน?)
- **เจอ:** ตัวการคือ **จำนวนคนที่ทำคำนั้นใน bank**
  | ชุด | คนต่อคำ | ทายถูก |
  |---|---|---|
  | ONE | 17 | 0.85 |
  | TTRS / THSL | 1 | ~0.18 |
  ในชุดเดียวกัน คำที่มี ≥ 5 คน ทายถูกเพิ่มจาก 0.17 → 0.50
- **ไม่ใช่**มือหาย / มุมกล้อง → เป็นเหตุผลว่าทำไม "บิดภาพ" (ข้อ 4, 6, 13, 14) ไม่ช่วยเลย
- THSL 72% เป็นคำที่**ไม่มีใน bank เลย** (ศัพท์ข่าว ชื่อนักการเมือง)

### ข้อ 16 — รวมชื่อคำที่ซ้ำกัน ⚪
- **ไอเดีย:** bank มีคำเดียวกันหลายชื่อ เช่น `ฝรั่ง` กับ `ฝรั่ง (ภาษามือโรงเรียนเศรษฐเสถียรฯ)` → ทายถูกแต่นับผิด และตัวอย่างกระจาย
- **ทำยังไง:** หาคู่จากชื่อ (408 คู่) → เช็กว่าท่าเหมือนกันจริงด้วยข้อมูล train → รวม 160 คู่
- **ผล:** คำเดี่ยวดีขึ้นเล็กน้อย (0.480 → 0.487) แต่ประโยคไม่ต่าง → **ยังไม่ใส่ในระบบ**

### ข้อ 17 — ลองวิดีโอจาก Drive 📹
**data_test (5 ประโยค):** ทายถูก 11/22 คำ (50%)
- ตัวอย่าง: "พ่อดื่มน้ำ" → ระบบได้ "ศูนย์ พ่อ น้า เกิด ศูนย์"
- **ข้อสังเกต:** เฉลยเขียนเรียงแบบภาษาไทย ("พ่อ ดื่ม น้ำ") แต่ท่าจริงเรียงแบบภาษามือ ("พ่อ น้ำ ดื่ม") → ตัวเลข WER ดูแย่เกินจริง

**jack_test (คลิปคำเดี่ยว/ตัวอักษร):**
- คำเดี่ยวที่ระบบไม่เคยเห็น: ถูก **91%**
- ตัวอักษร J A C K F R: **0%** ถ้าไม่เปิดโหมดสะกดนิ้ว (ปิดอยู่เป็นค่าเริ่มต้น) → เปิดแล้ว **88–92%**

**คำถาม "ไหม":** มาจากสีหน้า (คิ้ว) — พบว่าระบบ**ปิดการตรวจนี้ไว้**เป็นค่าเริ่มต้น และใช้ "คิ้วขมวด" ไม่ใช่ "คิ้วยก"

### ข้อ 18 — หาว่าประโยคพังตรงไหน 🔍 (ข้อค้นพบสำคัญที่สุด)
**ทดลอง 1 — ระบบรู้จักคำไหม?** ไล่ดูทุกช่วงเวลาในวิดีโอว่ามีช่วงไหนที่คำในเฉลยได้อันดับ 1
| | มีช่วงที่ได้อันดับ 1 |
|---|---|
| คำในเฉลย | **86%** |
| คำสุ่ม (ตัวเทียบ) | 4% |
→ **ระบบรู้จักคำ!** แต่ผลจริงได้แค่ 50% → ที่หายไป ~36% เกิดตอน**ตัดช่วงคำ**

**ทดลอง 2 — ดูกราฟ timeline** (`cache/analysis/timeline_*.png`): ในคลิปที่ทำท่าต่อเนื่อง tagger บอกว่า "กำลังทำท่า" **ตลอดทั้งประโยค ไม่มีจุดที่บอกว่าคำจบ** → ตัวตัดคำต้องเดา เช่น ช่วงที่ระบบเรียก "ข้าว" จริงๆ มีท่า "ด้วยกัน" + "กิน" อยู่ข้างใน

**ทดลอง 3 — ทำไมไม่เคยเจอปัญหานี้มาก่อน?**
| ข้อมูล | tagger เห็นรอยต่อ (ช่วงต่อคำ) |
|---|---|
| TSL51 (ที่ใช้ปรับค่ามาตลอด) | 0.97 — ทำท่าช้า **ค้างมือนิ่ง ~1 วินาที** ระหว่างคำ (ไม่ได้ลดมือพัก) |
| ประโยคปลอมที่ใช้ train tagger | ~1.0 — **มีช่วงหยุดนิ่งทุกคำ** |
| วิดีโอจริงทำท่าต่อเนื่อง | **0.25** |
→ ข้อมูลที่ใช้ทั้ง train และวัดผล **ไม่มีแบบทำท่าลื่นต่อเนื่องเลย** ปัญหาเลยซ่อนอยู่มาตลอด

**แก้ความเข้าใจ (2026-10-11):** TSL51 ส่วนใหญ่ (228/252) อัดแบบ `no_space` และคน**ไม่ได้ลดมือพัก** (มือนิ่ง+ต่ำ 1–2% เท่ากับวิดีโอจริง) — แต่ทำ**ช้ากว่า** (2.4 vs 1.7 วินาที/คำ) และ**ค้างมือนิ่ง**ระหว่างคำมากกว่า (42% vs 30% ของเฟรม) · ครึ่ง test ที่ tagger ไม่เคยเรียนก็ได้ 1.07 ท่อน/คำ → tagger เห็นรอยต่อจริง ไม่ใช่เพราะจำได้ · ลองตัดช่วงค้างออก ก็ยังเห็นรอยต่อ (0.70) → ต่างที่**สไตล์การทำท่า**ด้วย

### ข้อ 19 — ลองแก้ที่ "ตัวตัดคำ" (ปรับตัวเลข) ❌
- **ไอเดีย:** ถ้า tagger ไม่บอกรอยต่อ ลองปรับค่า `lam` (ค่าปรับต่อ 1 คำ — สูง = ตัดน้อยคำ)
- **ทำยังไง:** จำลองปัญหาบน TSL51 โดย**บังคับ tagger ให้มองไม่เห็นรอยต่อ** แล้วลองหลายค่า
- **ผล:** `lam` 12 ช่วยตอนทำท่าความเร็วปกติ (−0.10) แต่ทำท่าเร็ว 1.5×/2× **แย่ลง +0.12** → ค่าที่ดีขึ้นกับความเร็ว ซึ่งระบบไม่รู้ → **ไม่ใช้**

### ข้อ 20 — สร้าง "ประโยคปลอมแบบลื่น" ✅ (หัวใจของรอบนี้)
**ไอเดีย:** ถ้า tagger เรียนจากประโยคปลอมที่มีช่วงหยุดนิ่ง ก็ทำประโยคปลอมที่**ไม่มี**ช่วงหยุดนิ่ง

```
ประโยคปลอมแบบเดิม:  [ยกมือ][หยุด][ ท่า ฉัน ][หยุด][ลดมือ]—[ยกมือ][หยุด][ ท่า รัก ][หยุด][ลดมือ]
                                                     ↑ รอยต่อชัดมาก
ประโยคปลอมแบบลื่น:          [ ท่า ฉัน ]≈≈[ ท่า รัก ]≈≈[ ท่า เพื่อน ]
                                       ↑ ตัดหัว-ท้ายท่าทิ้ง + เชื่อมให้กลืนกัน
ของจริง (ทำท่าต่อเนื่อง):    ฉันรักเพื่อน (ไม่มีรอยต่อให้เห็น)
```

**วัดความเหมือนจริงยังไง (โดยไม่ต้องใช้วิดีโอจริง):** ใช้ tagger ตัวเดิม (v7) เป็น "เครื่องตรวจรอยต่อ" — ถ้ามันยังตัดประโยคปลอมได้ทุกคำ แปลว่ายังไม่เหมือนจริง · เป้า = 0.25 ช่วงต่อคำ (เท่าวิดีโอจริง)

**ลองหลายแบบ (6 รอบ ~30 แบบ):**
| แบบ | ช่วงต่อคำ ↓ | ผล |
|---|---|---|
| แบบเดิม | 1.05 | – |
| ตัดแค่ช่วงยก/ลดมือ | 1.08 | ไม่ช่วย |
| **ตัดหัว-ท้ายท่า 20%** + ซ้อนรอยต่อ | 0.61 | ✅ ช่วยมาก |
| ตัดหัว-ท้าย 30% + ซ้อนรอยต่อ | 0.48 | ✅ |
| เชื่อมรอยต่อให้ช้าลง / ไม่ให้มือตก / ผสมรูปมือแบบสมจริง / ล็อกหัว-ตัวให้นิ่ง | 0.46–0.68 | ❌ ไม่ช่วย |
| **ตัดหัว-ท้าย 40% + ซ้อนรอยต่อ 6–12 เฟรม** | **0.42** | ✅ ดีที่สุด |
| ตัดหัว-ท้าย 45% | 0.54 | ตัดเกิน แย่ลง |
| เป้า (วิดีโอจริง) | 0.25 | |

**สิ่งที่เรียนรู้:** ตัวที่ทำให้ tagger เห็นรอยต่อคือ **"การหยุดนิ่งตอนเริ่ม/จบท่า"** ของคลิปคำเดี่ยว — ตัดทิ้งได้ผลที่สุด · รายละเอียดอื่นของรอยต่อไม่สำคัญ

### ข้อ 21 — สอน tagger ใหม่ด้วยประโยคแบบลื่น (GPU L4 บน Modal) ✅
**ทำยังไง:**
1. เพิ่มตัวเลือก `--fluent` ในโค้ด train (`modules/sequence.py`) = สัดส่วนประโยคแบบลื่น (0 = เหมือนเดิมทุกอย่าง)
2. train หลายตัว (ทุกตัวเหมือนกันหมด ต่างแค่ตัวเลือกนี้):
   | ชื่อ | ประโยคแบบลื่น | วิธีทำประโยคลื่น |
   |---|---|---|
   | **B** (ตัวควบคุม) | 0% | – |
   | **A 50%** | 50% | ตัดหัว-ท้าย 15–30% |
   | **A 25%** | 25% | ตัดหัว-ท้าย 15–30% |
   | **v2** | 25% | ตัดหัว-ท้าย 30–40% + ซ้อน 6–12 เฟรม (ลื่นกว่า) |
3. สร้าง**ชุดวัดผลใหม่** = ประโยคปลอมแบบลื่นจากคลิปของคน**ที่ไม่อยู่ใน train** 240 ประโยค (2 แบบ: "same" ง่ายกว่า · "diff" ยากกว่า)

**ผลบนส่วน tune (ใช้เลือก):**
| | v7 (เดิม) | B | A 50% | **A 25%** | v2 |
|---|---|---|---|---|---|
| ประโยคลื่น "diff" WER ↓ | 0.806 | 0.794 | **0.682** | 0.721 | 0.683 |
| ประโยคลื่น "same" WER ↓ | 0.556 | 0.528 | 0.513 | **0.483** | 0.489 |
| TSL51 1× WER ↓ (ห้ามแย่ลง) | **0.393** | 0.396 | 0.429 ❌ | 0.415 | 0.434 ❌ |
| TSL51 เฉลี่ย 3 ความเร็ว | **0.380** | 0.385 | 0.403 | 0.396 | 0.407 |

- **B ≈ v7** → แค่ train ใหม่ไม่ได้ช่วย ที่ดีขึ้นมาจาก "ประโยคแบบลื่น" จริง
- **A 50% / v2** ช่วยประโยคลื่นมาก แต่ทำ TSL51 1× **แย่ลงจริง** (CI ไม่คร่อม 0) → ตกเกณฑ์
- **A 25%** = จุดสมดุล: ช่วยประโยคลื่น + TSL51 1× แย่ลงนิดหน่อยแต่**ไม่มีนัยสำคัญ** → **เลือกตัวนี้**
- **ทำไมยิ่งลื่นยิ่งเสีย TSL51:** ประโยคปลอมที่ลื่นมากมีท่าสั้นมาก (~13 เฟรม/คำ) tagger เลยชินกับท่าสั้น → เจอท่าช้าๆ แบบ TSL51 ก็หั่นเป็น 2 คำ

**ผลบนส่วน test (เปิดครั้งเดียว) — A 25% เทียบ v7:**
| ชุด | v7 | **A 25%** | ต่าง (95% CI) | สรุป |
|---|---|---|---|---|
| ประโยคลื่น "diff" — WER | 0.758 | **0.668** | −0.089 [−0.143, −0.042] | ✅ ดีขึ้นจริง |
| ประโยคลื่น "diff" — ทายถูก | 0.246 | **0.344** | +0.098 [+0.049, +0.152] | ✅ ดีขึ้นจริง |
| ประโยคลื่น "diff" — ตัดได้กี่คำ (จริง 4.08) | 1.97 | **2.85** | | ✅ แยกคำได้มากขึ้น |
| ประโยคลื่น "same" — ทายถูก | 0.492 | **0.528** | +0.036 [+0.004, +0.070] | ✅ ดีขึ้นจริง |
| TSL51 1× | 0.424 | 0.432 | +0.008 [−0.021, +0.036] | ✅ ไม่แย่ลง |
| TSL51 1.5× | 0.380 | 0.374 | −0.006 | ✅ ไม่แย่ลง |
| TSL51 2× | 0.394 | 0.386 | −0.008 | ✅ ไม่แย่ลง |
| **data_test (วิดีโอจริง)** — ทายถูก | 11/22 | 10/22 | ต่าง 1 คำ | ⚪ เท่าเดิม |
| data_test — จำนวนคำที่ตัดได้ ห่างจากจริง | 1.0 | **0.6** | | ใกล้จริงขึ้นนิดหน่อย |

### ข้อ 21b — ทดสอบเพิ่มกับ "ท่าของคนจริง" ที่ทำให้ลื่นขึ้น (TSL51 ตัดช่วงค้าง) ✅
- **ไอเดีย:** ประโยคลื่นในข้อ 21 เป็นประโยคปลอม → อยากได้หลักฐานจาก**ท่าของคนจริง** · เอา TSL51 ครึ่ง test แบบ `no_space` (114 ประโยค, tagger ไม่เคยเรียน) มา**ตัดช่วงที่มือค้างนิ่งระหว่างคำออก** (`pitty/scripts/hold_cut.py`) — ท่าและการเปลี่ยนท่ายังเป็นของคนจริงทั้งหมด
- ตั้งค่าการตัดเลือกด้วย tagger v7 เท่านั้น (ไม่ได้ดูผลของ tagger ใหม่) → ตัดแรงสุดที่ยังสมจริง: ท่อนต่อคำ 1.07 → 0.74, 2.4 → 1.26 วินาที/คำ

| tagger | WER ↓ | ทายถูก ↑ | คำหาย | ตัดได้ / จริง |
|---|---|---|---|---|
| v7 (เดิม) | 0.630 | 0.377 | 0.365 | 2.29 / 3.58 |
| B (ตัวควบคุม) | 0.614 | 0.390 | 0.358 | 2.31 / 3.58 |
| **A 25%** | **0.581** | **0.423** | **0.331** | **2.40 / 3.58** |

- **A 25% − v7:** WER **−0.049** [−0.086, −0.013] ✅ · ทายถูก **+0.046** [+0.010, +0.083] ✅ → **ดีขึ้นจริงบนท่าของคนจริง**
- A 25% − B: −0.033 [−0.070, +0.002] (เกือบมีนัยสำคัญ) · B − v7: ไม่ต่าง → ที่ดีขึ้นมาจากประโยคแบบลื่นเป็นหลัก
- ข้อจำกัด: ยังไม่ใช่การทำท่าลื่นตามธรรมชาติ (tagger v7 ยังเห็นรอยต่อ 0.74 vs 0.25 ของจริง)

### ข้อ 22 — ลองเว็บเดโมจริง (docker) 🖥️
- build เว็บเดโมในเครื่อง (ต้องล้าง docker cache ~37 GB ก่อน เพราะไดรฟ์ C เต็ม)
- เว็บอ่านโมเดลจาก `models/` โดยตรง → ใช้ tagger A 25% อัตโนมัติ
- **ผลที่สังเกต:** จับมือได้ดีกว่าตอนเพื่อนสาธิต → น่าจะมาจาก**การปิดปรับแสงอัตโนมัติ (ข้อ 1)** ไม่ใช่ tagger (tagger ทำงานหลังจากจับมือได้แล้ว) — เป็นการสังเกต ยังไม่ได้วัดเป็นตัวเลข

## 6. ข้อควรรู้ / สิ่งที่พลาดและแก้แล้ว
- **data_test ถูกดูมากกว่าที่ตั้งใจ** 2 ครั้ง: (1) เทียบ tagger ข้อ 6 (ดูแค่รอยต่อ — ได้รับอนุญาต) (2) ตอนเปิด test มีรอบหนึ่งใช้ tagger A 50% โดยไม่ตั้งใจ (เพราะ `models/` ถูกเปลี่ยนแล้ว) — ตัวเลขในไฟล์นี้แก้เป็นของจริงแล้ว
- **ประโยคแบบลื่นที่ใช้วัดผล ทำด้วยวิธีคล้ายตอน train** → อาจเข้าข้าง tagger ใหม่บ้าง · ตัวตัดสินที่เป็นอิสระ = TSL51 (ผ่าน) + data_test (เท่าเดิม)
- **"เครื่องตรวจรอยต่อ" ต้องเป็น v7 เสมอ** — เคยพลาดใช้ tagger ใหม่เป็นตัวตรวจ (ตัวเลขเพี้ยน) แก้แล้ว
- รายงานในแชทบางจุดผิดแล้วแก้: โหมด "all" ของข้อ 13 รันเสร็จจริง · baseline เก่า `a0_x2.0` ไม่ตรงกับโค้ดปัจจุบัน (ใช้ `base2_x*` แทน) · ป้ายกราฟ timeline เส้นสีส้มคือ "อยู่ในท่า" ไม่ใช่ "เริ่มคำ"
- **GPU ที่ใช้ (Modal):** A100 ~40 นาที (ข้อ 14) + L4 ~5 รอบ (ข้อ 21 — 3 รอบแรกรันจนจบ ~1.5 ชม./รอบ, 2 รอบหลังหยุดทันทีที่ได้ tagger ~12–15 นาที)

## 9. อภิธานศัพท์
| คำ | ความหมายแบบง่าย |
|---|---|
| **keypoints / landmarks** | จุดบนร่างกายที่ MediaPipe หาได้ (ข้อมือ ข้อนิ้ว ไหล่ หน้า) — ระบบไม่ได้ดูภาพ แต่ดูจุดพวกนี้ |
| **encoder** | ตัวแปลงท่ามือ 1 ช่วง → ตัวเลขชุดหนึ่ง (embedding) ท่าเหมือนกัน = ตัวเลขใกล้กัน |
| **bank** | คลังคลิปตัวอย่างของทุกคำ ไว้เทียบว่าท่าที่เห็นเหมือนคำไหน |
| **tagger** | ตัวดูทีละเฟรมว่า "กำลังทำท่าไหม / คำใหม่เริ่มไหม" — ใช้หาจุดตัดคำ |
| **decoder / ตัวตัดคำ** | ใช้ผลจาก tagger ตัดวิดีโอเป็นช่วงคำ |
| **augmentation** | การ "บิด" ข้อมูลตอน train (หมุน ย่อ เร่ง) ให้โมเดลทนต่อความต่าง |
| **train / เทรน** | สอนโมเดลจากข้อมูล |
| **tune / val** | ข้อมูลส่วนที่ใช้**เลือก**ว่าแบบไหนดี |
| **test** | ข้อมูลส่วนที่เก็บไว้ดู**ครั้งเดียว**ตอนท้าย เพื่อรายงานผลที่เชื่อถือได้ |
| **ตัวควบคุม (control)** | โมเดลที่ train เหมือนกันทุกอย่าง ยกเว้นสิ่งที่อยากทดสอบ — ไว้เทียบ |
| **95% CI** | ช่วงที่ผลต่างจริงน่าจะอยู่ · ไม่คร่อม 0 = ต่างจริง · คร่อม 0 = อาจบังเอิญ |
| **WER** | % ความผิดของประโยค (ยิ่งต่ำยิ่งดี) |
| **R@1 / recall** | % ที่ทายถูก (ยิ่งสูงยิ่งดี) |
| **ประโยคปลอม / สังเคราะห์** | ประโยคที่สร้างจากการเอาคลิปคำเดี่ยวมาต่อกัน |
| **ช่วงต่อคำ** | tagger แยกประโยคได้กี่ช่วงต่อ 1 คำ — ใช้วัดว่าประโยคปลอม "ลื่นเหมือนจริง" แค่ไหน |
| **v7** | โมเดลเวอร์ชันของเพื่อน (ตัวตั้งต้น) |
| **A 25% / A 50% / B / v2** | tagger ที่เรา train ใหม่ (ดูข้อ 21) |
| **Modal** | บริการเช่า GPU บนคลาวด์ ที่ใช้ train |
| **ONNX** | รูปแบบไฟล์โมเดลที่เว็บเดโมใช้ (แปลงมาจาก PyTorch `.pt`) |
| **docker** | ตัวรันเว็บเดโมแบบครบชุดในเครื่อง |
