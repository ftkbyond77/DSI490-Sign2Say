# ชุดทดลองปรับปรุง Sign2Say

## สถานะจริง

ดำเนินการในชุดทดลองแยก ยังไม่ได้เปลี่ยนเว็บ production หรืออ้างว่าความแม่นดีขึ้น โฟลเดอร์ `models` นี้มี JSON ชุดทดลอง ส่วนไฟล์น้ำหนักและ bank เชื่อมไปยังต้นฉบับเพื่ออ่านเท่านั้น ห้ามเขียนทับไฟล์ที่เชื่อมไว้

## 1. ข้อมูลและ mapping

- เก็บสำเนา JSON baseline และ SHA-256 ของอินพุตแล้ว
- แก้ชื่อ concept `ทั้งหมด (ภาษามือโรงเรียนเศรษฐเสถียรในพระราชูปถัมภ์)` เป็น `ทั้งหมด` ในชุดทดลอง ที่ index 2511 เดิม คงจำนวน concepts 9,929 และ embeddings เดิม
- เพิ่ม concept นี้ใน vocabulary บทสนทนาทดลอง: 326 → 327 คำ ปรับ manifest 1 รายการ เก็บ gloss ต้นทางไว้
- ตรวจโครงสร้างผ่าน: ไม่มี concept ซ้ำ ทุก bank ID อยู่ในขอบเขต และ ID ของคำอื่นไม่เปลี่ยน
- ยังไม่พร้อมใช้งานจริง: roles_language.json มีบทบาทขัดกัน (`ADJ` สำหรับชื่อมีวงเล็บ และ `OBJ` สำหรับชื่อสั้น) จึงเก็บไฟล์ role เดิม ไม่ตัดสินใจรวมโดยเดา
- `ทำ`: manifest ระบุ `th_sl_00936.mp4` มี pose_missing; คลิปในเครื่อง `14265_ทำ.mp4` มีขนาดต่างจาก inventory ของต้นทางมาก ยังยืนยันว่าเป็นคลิปเดียวกันไม่ได้ ไม่เปลี่ยน missing flag และไม่แอบแทน source เก่า มีคิวซ่อมและ fingerprint คลิปที่พบแยกไว้

## 2. ทดสอบสองกลุ่ม

ใช้ผลเว็บ 6 คลิปจาก audit ก่อนหน้าเป็น smoke baseline เท่านั้น ไม่ถือเป็นข้อมูลคนใหม่ ยังขาดคลิปที่ระบุ ground truth ชัดเจนครบทั้ง 10 คำ โดยเฉพาะ ฉัน/ชา/ธนาคาร/จ่าย

กลุ่มตัวอย่างมาก: สวัสดี ขอบคุณ ชอบ ฉัน แม่

กลุ่มพจนานุกรม: กาแฟ ชา ธนาคาร ซื้อ จ่าย

ต้องใช้ผู้ทำท่าคนเดียวกันและเงื่อนไขบันทึกใกล้เคียงกันข้ามสองกลุ่ม เพื่อลดการปะปนของผลจำนวนข้อมูลกับคุณภาพคลิป แต่ผลต่างอย่างเดียวก็ยังไม่พิสูจน์สาเหตุ

## 3. Validation และ threshold

Mapping regression: คำนวณ retrieval จาก embeddings เดิมเฉพาะ role=val ตัด signer และ clip เดียวกันออกจาก gallery รวม 178 queries; ก่อน 125/178 หลัง 125/178 (70.22%) ไม่พบการเปลี่ยนคำตอบที่ถูกในคะแนนรวม คำ `ทั้งหมด` ไม่มี validation query จึงยังยืนยันการรู้จำคำนี้ไม่ได้ ไม่ใช่การรัน visual encoder หรือเว็บใหม่

Threshold diagnostic: อ่านคะแนนราย segment จากรายงาน phrases.json เดิมเฉพาะ split=tune จำนวน 26 วิดีโอ ไม่ใช้ split=test และไม่ได้ refit calibration ใช้การจับคู่ลำดับคำด้วย LCS เป็นตัวชี้วัดเบื้องต้น ไม่ใช่ ground truth ของขอบเขต segment

|threshold|คำที่ผ่าน|ตรงลำดับคำอ้างอิง|ไม่ตรง|
|---|---:|---:|---:|
|0.80|0|0|0|
|0.60|2|0|2|
|0.50|8|2|6|
|0.40|12|3|9|
|0.20|26|8|18|

ตัวเลขมาจากผลโมเดลในรายงานเก่า ไม่ใช่ผลใหม่ของชุด mapping ทดลอง จึงใช้แสดงความเสี่ยงของการลด threshold เท่านั้น ไม่ใช่หลักฐานเลือก threshold ที่เหมาะสม รักษาค่า production 0.8 และยังไม่ประกาศว่า calibrate สำเร็จ

## 4. แผนวัดก่อน–หลังที่รอข้อมูล

1. กำหนด signer IDs จริง, clip hash, label และ split ก่อนทดลอง; คนใน validation ต้องแยกจากคนใน test และตรวจไม่ปะปนชุด train/bank ตาม provenance ที่มี
2. เก็บ clips ชุด test คงที่ ใช้เหมือนกันทุก variant; ห้ามปรับค่าจากผล test หากดูเพื่อปรับแล้วต้องเปลี่ยนสถานะเป็นข้อมูลพัฒนา
3. ทดลองทีละตัวแปร: baseline → mapping-only → pose-repair-only → threshold-only → combined หลังผ่าน validation
4. รายงาน Top-1/Top-5, accepted-correct, accepted-wrong, rejected-correct, rejection rate, extraction failure และ latency; แยกต่อคำ/กลุ่ม/คน ทั้ง micro และ macro ไม่ใช้ accepted precision อย่างเดียว
5. เลือก threshold จาก validation ด้วยเงื่อนไขที่ตกลงก่อนเห็น test; บันทึกไฟล์ config/hash แล้วประเมิน test ครั้งเดียวสำหรับ variant ที่ล็อกไว้

สถานะที่ยังรอ: คลิปคนใหม่ครบสองกลุ่ม, labels/timestamps ที่ตรวจยืนยันได้สำหรับ calibration, การตรวจบทบาทคำ “ทั้งหมด”, การยืนยันคลิปต้นทาง “ทำ” และสกัดด้วย pipeline เดียวกับ production ผลก่อน–หลัง end-to-end ยังไม่มี
