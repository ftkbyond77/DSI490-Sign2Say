# ทดลองรวมช่วงคลิป 2

ใช้ landmarks เดิม คลิป 2 เท่านั้น คง reflection เดิม (ไม่สะท้อน) คลัง 326 คำ และน้ำหนักเดิม ไม่ใช้คลิป 3 ไม่แก้ production

ช่วงที่ผู้ใช้เสนอ: รวม [36,68) กับ [68,112) เป็น [36,112) ที่ 25 fps = 1.44–4.48 วินาที

|วิธีให้คะแนน|ช่วง 2 แยก|ช่วง 3 แยก|ช่วงรวม|
|---|---|---|---|
|Temporal ensemble ตามกติกา decoder|เพื่อน; ภาษามือ #3|กรุงเทพ; ภาษามือ #2|ภาษามือ #1|
|Span-head embedding ทั้งช่วง|ภาษามือ #1|กรุงเทพ; ภาษามือ #2|กรุงเทพ; ภาษามือ #2|
|Exact encoder สกัด embedding ของช่วงใหม่|เพื่อน; ภาษามือ #7|กรุงเทพ; ภาษามือ #2|กรุงเทพ; ภาษามือ #2|

Temporal ensemble ของช่วงรวมใช้ 108 windows ตาม grid เดิม (max length 48 เฟรม จึงไม่มี window เดียวยาวครบ 76 เฟรม) แล้วรวมคะแนนสนับสนุนของคำตามกติกาเดิม:

|อันดับ|คำ|support|peak cosine-derived score|
|---:|---|---:|---:|
|1|ภาษามือ|0.3383|0.4941|
|2|กรุงเทพ|0.2782|0.4673|
|3|ข้าว|0.1699|0.5311|
|4|ขอโทษ|0.1561|0.4848|
|5|กิน|0.1375|0.5040|

คะแนน support ใช้จัดอันดับ ไม่ใช่ p(correct) ส่วน peak เป็น max ของคะแนน concept ต่อ window ซึ่ง Bank.scores รวมตัวอย่างจาก cosine ตามกติกา top-2 เดิม

Exact encoder ช่วงรวม: กรุงเทพ 0.318886, ภาษามือ 0.317610 ต่างเพียง 0.001276 แต่ภาษามือยังเป็นอันดับ 2 ส่วน span-head ช่วงรวมเป็นกรุงเทพ 0.335394 กับภาษามือ 0.299319

ข้อสรุป: ผลสนับสนุนสมมติฐาน merge ร่วมกับ temporal ensemble ในคลิปพัฒนานี้ แต่ไม่ใช่ทุกวิธีการให้คะแนนที่ดีขึ้น และยังไม่ได้สร้างกฎ merge อัตโนมัติที่ใช้กับคลิปอื่นได้ ไม่คำนวณ p ใหม่ด้วย calibration เดิมอย่างไม่ตรวจสอบ เพราะขอบเขต/features เปลี่ยน การรวมท่าคนละคำเป็นความเสี่ยงที่ต้องตรวจด้วยตัวอย่างหลายคำจริง

พัก symbolic reranking สำหรับสวัสดีในคลิป 1 ตามคำขอ ไม่มีการใช้กฎ if-word=ภาษามือ เพื่อบังคับคำตอบ ก้าวถัดไปคือทดสอบเกณฑ์ merge ที่ใช้คะแนน/ความต่อเนื่องทั่วไปบนชุดพัฒนา และตรวจกรณีที่ไม่ควรรวม ก่อนล็อกกฎไปวัดคลิป heldout
