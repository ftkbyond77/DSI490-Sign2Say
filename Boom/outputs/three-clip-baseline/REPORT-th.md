## เส้นทางทดสอบ

Python MediaPipe CPU ยังล้มเหลวใน Metal helper บนเครื่องนี้ จึงใช้ browser upload ของเว็บ localhost:3010 และบันทึก requests ที่มี landmarks/result จาก server สองคลิป ไม่มี personal examples ณ ตอนส่ง request (n_user_signs=0) ตั้ง conversation 326, threshold 0.8, LLM off, speech off, spelling off, exposure correction on

รัน replay ผ่าน ONNX บน CPU ด้วย landmarks เดิมแล้ว ได้คำและคะแนนตรงกับ server หลังปัดทศนิยม จึงใช้ข้อมูลเดิมเปรียบเทียบการเปลี่ยน vocabulary โดยไม่ต้องสกัดซ้ำและไม่ส่งไปบริการภายนอก

## ทดลองแล้ว: เพิ่ม “คุย” อย่างเดียว

คลัง conversation มี “สวัสดี” และ “ภาษามือ” แต่ไม่มี “คุย”; คลังเต็มมี “คุย” จึงสร้าง models_add_talk ที่เพิ่ม concept เดิมเข้าคลังทดลอง 327 คำ โดยไม่เปลี่ยน embedding, threshold, segmenter หรือสอนท่าตัวอย่างส่วนตัว ไม่รวม mapping “ทั้งหมด” จากการทดลองก่อนหน้าเพื่อแยกตัวแปร

ผล: Top-1 ทุกช่วงยังเหมือน baseline ไม่มีคำผ่านเกณฑ์ ไม่มีหลักฐานว่าการเพิ่ม vocabulary อย่างเดียวแก้กรณีนี้ได้ จึงยังไม่แทนที่โมเดล/คลังคำ production

## สิ่งที่ควรตรวจต่อ

1. ตรวจวิดีโอตามเวลาและให้ผู้รู้ภาษามือยืนยันหน่วยท่าจริง ก่อนตีความคำผิด/คำหาย
2. ดูการสกัดมือและการเลือกสะท้อนมือที่ต่างกันสองคลิป เปรียบเทียบวิธีเดิมกับการแก้ทีละอย่างเฉพาะชุดพัฒนา
3. คง threshold 0.8 ไว้ตอนตรวจ recognition; ลดเกณฑ์ตอนนี้จะทำให้ “ข้าว/เพื่อน/กรุงเทพ” หลุดเป็นคำที่ยอมรับได้
4. เมื่อเลือกการแก้และล็อกค่าแล้ว จึงรัน baseline กับรุ่นแก้บน clip3 เดียวกัน ห้ามใช้ผล clip3 ปรับค่าแล้วอ้างว่าเป็น held-out ต่อไป

ผลตอนนี้คือ baseline และการทดลอง vocabulary ที่ไม่ช่วย ไม่ใช่ผลว่าระบบดีขึ้นแล้ว และยังไม่ทดสอบครบ 10 คำสองกลุ่ม
